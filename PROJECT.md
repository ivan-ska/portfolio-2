# Портфолио: главная страница

Сайт-портфолио на **React + Vite**. Карточки проектов (название, превью, теги) берутся из **Google Таблицы**, поэтому для правки контента код трогать не нужно. Раскладка как в Pinterest (masonry).

- Макет (1440px): [Figma, frame 4553:21255](https://www.figma.com/design/pYkY75Ezip3ugv30EUvPCy/?node-id=4553-21255)
- Таблица: [portfolio website main](https://docs.google.com/spreadsheets/d/1pnzyYj-AiN_Fnu-Ul1sIxMGURj48NZmY_lajxVsv0Fk/edit)
- Превью проектов лежат в Dropbox
- Декор из макета уже выгружен из Figma: [public/decor/](public/decor/). **Пока не используется**, вернёмся к нему позже.

## 1. Как работает автообновление

```
Google Таблица ──▶ сайт при каждом открытии читает таблицу ──▶ рисует карточки
                                                                  │
Dropbox ◀──────────────── картинки грузятся по ссылкам из таблицы ┘
```

Сайт **не хранит данные внутри себя**. Каждый раз, когда кто-то открывает страницу, браузер заново скачивает таблицу и строит карточки по ней. Поэтому:

- поправил таблицу, обновил страницу, увидел изменения. Задержка обычно около минуты (кэш Google);
- пересобирать или перезаливать сайт после правок контента **не нужно**;
- код меняется, только если меняется **дизайн** или **логика**.

### Что для этого должно быть выполнено (уже выполнено ✅)

| Условие | Статус |
|---|---|
| Доступ к таблице «Все, у кого есть ссылка → Читатель» | ✅ проверено, сайт может её читать |
| Ссылки на картинки в Dropbox открыты для всех | ✅ все 12 загружаются |
| Названия колонок в первой строке не меняются | ⚠️ просто не трогай их |

Сайт читает таблицу по адресу:
```
https://docs.google.com/spreadsheets/d/1pnzyYj-AiN_Fnu-Ul1sIxMGURj48NZmY_lajxVsv0Fk/gviz/tq?tqx=out:csv&gid=0
```
`gid=0` — это номер первой вкладки, поэтому вкладку `Лист1` можно спокойно переименовать.

### Словарик

| Слово | Что это |
|---|---|
| **React** | Способ собирать страницу из «компонентов». Как компоненты в Figma: одна `Card` и много её копий с разными данными. |
| **Vite** | Инструмент, который запускает сайт у тебя на компьютере и собирает финальную версию для хостинга. |
| **CSV** | Таблица в виде текста. Google умеет отдавать её по ссылке. |
| **Masonry** | Pinterest-раскладка: колонки одинаковой ширины, у карточек разная высота, без пустых «дыр». |

| Команда | Что делает |
|---|---|

| `npm run dev` | Запускает сайт локально. Ссылка появится в терминале, обычно http://localhost:5173 |

## 2. Таблица

Одна строка = одна карточка. **Порядок строк = порядок на сайте.** Пустые строки пропускаются.

| Колонка | Пример | Что делает на сайте |
|---|---|---|
| `Name` | `Colibrix One rebranding` | Название под превью. Если длинное, обрезается троеточием в одну строку. |
| `Thumbnail link` | ссылка «Поделиться» из Dropbox | Превью. Ссылку вставляешь как есть, с `dl=0` на конце: код сам переделает её в прямую ссылку на картинку. |
| `Year` | `2026` | На главной пока не показывается. Пригодится для сортировки или страницы кейса. |
| `Field 1`, `Field 2`, `Field 3` | `Web`, `Graphic`, `UI/UX` | Теги, слева направо в том же порядке. Пустые ячейки игнорируются. Можно добавить `Field 4` и дальше: код подхватит. |

### Как добавить проект

1. Экспортируй превью: ширина **1080px**, высота — какая нужна карточке, формат WebP.
2. Залей файл в Dropbox → «Поделиться» → «Скопировать ссылку».
3. Вставь в таблицу новую строку в нужное место, заполни `Name`, ссылку и теги.
4. Обнови сайт.

### Превью и высота карточек

Высота карточки = **пропорция самой картинки**. Сейчас все превью уже обрезаны под макет:

| Размер файла | Проекты |
|---|---|
| 1080 × 1080 | Colibrix, Embacy |
| 1080 × 720 | eCards interface, eCards Premium, Interface pieces, +Plus |
| 1080 × 550 | Converter, nuk, Makers PR |
| 1080 × 865 | dazzl3 |
| 1080 × 620 | Qelvio |
| 1080 × 1528 | PRA |

Чтобы поменять высоту карточки, перевыгрузи картинку с другой высотой. Код и таблица остаются как есть.

### Теги

Стиль известных тегов задан в коде (см. раздел 3). **Новый тег** (например `Motion`) появится на сайте сразу, но в нейтральном сером стиле. Свой цвет и форма для него — одна строка в коде.

Чтобы не опечататься (`UI/UX` и `UI / UX` для кода разные теги), на колонки `Field` можно поставить выпадающий список: выдели колонки → **Данные → Настроить проверку данных → Раскрывающийся список** → `Web`, `Graphic`, `UI/UX`.

### Чего лучше не делать

- Переименовывать заголовки `Name`, `Thumbnail link`, `Field …` и вставлять строки над ними.
- Закрывать доступ к таблице или к файлам в Dropbox: картинки и карточки пропадут.
- Хранить в таблице приватное: её может прочитать любой, у кого есть ссылка.

Добавлять свои колонки (например `Notes`) и менять колонки местами можно: код ищет колонки по названию.

### Про Dropbox

Работает, но это не специализированный хостинг картинок. Картинка открывается через пару редиректов, поэтому грузится чуть медленнее. У бесплатного аккаунта ещё есть дневной лимит трафика на расшаренные ссылки, для портфолио с запасом. Если заменить файл в Dropbox **с новой ссылкой**, ссылку в таблице надо обновить.

### Поведение карточки

- **Ховер на всей карточке** (превью + подпись): превью плавно увеличивается внутри рамки (`scale(1.04)`, 0.2 с). Только на устройствах с мышью: на телефоне после тапа ховер «залипает».
- **Длинное название** не переносится: правый край растворяется градиентом шириной 40.
- **При ховере** такое название едет бегущей строкой по кругу, растворяясь с обоих краёв. Когда курсор уходит, текст за 0.3 с плавно возвращается на место.
- **На тач-экранах** (телефон, планшет) ховера нет, поэтому длинные названия едут сами. Анимация идёт только у названий, которые сейчас видно на экране, чтобы не тратить батарею.
- Если в системе включено «Уменьшить движение», бегущая строка и анимации отключаются.

### Хиро-блок (Figma, node 4583-2279)

Над сеткой проектов: фото, папка с именем, листок CV, кнопки Mail и Telegram. Масштабируется по тем же правилам, что и сетка.

| Ширина | Раскладка |
|---|---|
| 3–4 колонки | одна строка: фото 345 · папка 464 · CV 226 · контакты на всю оставшуюся ширину, высота 345. На очень широких экранах контакты не шире 570: вместо этого весь хиро крупнеет (`HERO_CONTACTS_MAX` в [scale.js](src/lib/scale.js)) |
| 2 колонки | две строки: фото + папка (растянуты на всю ширину сетки), ниже CV (мобильный листок, высота 295) + контакты |

При 2 колонках у хиро своя единица `--hero-u`: верхняя строка (345 + 12 + 464 = 821) всегда занимает ровно ширину сетки.

**Цвета секции** заданы переменными в начале [Hero.css](src/components/hero/Hero.css):

| Переменная | Цвет | Где |
|---|---|---|
| `--hero-folder` | `#C6A886` | папка |
| `--hero-folder-text` | `#776550` | More, Visual designer |
| `--hero-paper` | `#D3DEE2` | листок CV и листок за папкой |
| `--hero-paper-corner` | `#B3C4CC` | загнутый уголок |
| `--hero-paper-text` | `#92A4AC` | CV и скрепка |
| `--hero-mail` | `#028565` | Mail |
| `--hero-telegram` | `#457CAA` | Telegram |

**Ховеры** (только с мышью, длительность 0.35 с, плавное замедление в конце):
- Папка: листок за папкой выравнивается из наклона 5°, стрелка ↖ наклоняется на −10°.

**Ссылки** (почта, ник в Telegram, PDF с резюме) задаются в `CONTACTS` в [src/config.js](src/config.js). Пока там пусто, элементы выглядят так же, но не кликаются. «More» пока никуда не ведёт: подключим, когда будет страница «обо мне».

## 4. Масштаб и колонки

Все размеры из макета записаны в «единицах макета» и умножаются на `--u`. Поэтому сайт на любой ширине выглядит как макет, увеличенный или уменьшенный целиком. В CSS это пишется так: `font-size: calc(28 * var(--u));`.

Число колонок выбирается так, чтобы ширина каждой была как можно ближе к 464 из макета:

| Ширина окна | Колонок | Ширина колонки |
|---|---|---|
| до ~1190px | 2 (минимум) | растёт до ~570 |
| ~1190 – 1666px | 3 (как в макете) | ~385 – 535, при 1440 ровно 464 |
| от ~1666px | 4 (максимум) | от ~405 и дальше растёт |

Боковые отступы всегда 12 единиц, поэтому широких полей по краям нет.

### Мобильное увеличение

Если на телефоне просто уменьшить макет, всё становится крошечным. Поэтому на узких экранах текст, теги, отступы и скругления крупнее, чем при пропорциональном уменьшении. Колонок по-прежнему 2 на всю ширину.

| Ширина окна | Увеличение элементов | Название / тег при этой ширине |
|---|---|---|
| от 900px | нет, чистый макет | 1440 → 28 / 22px |
| 768px | +9% | 24 / 19px |
| 600px | +19% | 21 / 17px |
| 480px и уже | +30% | 390 → 15 / 12px |

Между 900 и 480 увеличение нарастает плавно, без скачков. Настраивается в [src/lib/scale.js](src/lib/scale.js): `MOBILE_BOOST` (сила, сейчас 0.3 = +30%), `BOOST_FROM` и `BOOST_FULL` (где начинается и где выходит на максимум).

В CSS для этого две переменные:
- `--u` — единица макета, уже с увеличением. Через неё задаются все размеры элементов.
- `--col-width` — ширина колонки.
- `--hero-u` — единица хиро-блока (при 3–4 колонках равна `--u`).

## 5. Раскладка (Pinterest)

1. Карточки идут **по порядку строк** таблицы, каждая в **самую короткую** на данный момент колонку. Поэтому верхний ряд читается слева направо.
2. Чтобы колонки **заканчивались примерно на одной высоте**, последние 7 карточек перебираются во всех возможных порядках, и выбирается самый ровный. Верх сетки не меняется.
3. Сначала нужно узнать пропорции превью. Пока ни одна картинка не загрузилась, видны серые плашки. Дальше карточки появляются по мере загрузки.

Сейчас на 1440 колонки заканчиваются на 1610 / 1658 / 1621 px. Без шага 2 было бы примерно 2040 / 1330 / 1515.

### Блоки с иконками в сетке

Алгоритм в [src/lib/masonry.js](src/lib/masonry.js):

1. Для каждой колонки заранее случайно решается, после какой по счёту карточки в ней встанет блок и из скольких он иконок. У соседних колонок номера разные.
2. Когда в колонку приходит нужная карточка, под ней встаёт блок. Если в соседней колонке блок ближе чем в 160 единицах по вертикали (`DECOR_SPACING`), ждём следующую карточку этой колонки.
3. При переборе последних 7 карточек в конец каждой колонки пробуется: ничего, блок из 4 или из 5 иконок. Выбирается вариант, где колонки кончаются ровнее и блоки не стоят рядом.
4. Правила: в каждой колонке 1–2 блока, два блока подряд в одной колонке не встают.

Верх сетки от загрузки картинок не меняется: блоки наверху ставятся сразу, вместе с карточками.

> Почему не CSS `columns`: он раскладывает карточки сверху вниз по первой колонке, потом по второй, и порядок из таблицы ломается.

## 6. Страницы без перезагрузки

Сайт — одна HTML-страница. Переходы делает **React Router**: адрес в браузере меняется, «назад» и «вперёд» работают, прокрутка главной восстанавливается при возврате. Таблица при переходах заново не скачивается.

| Адрес | Страница |
|---|---|
| `/` | главная (сетка) |
| `/projects/colibrix-one-rebranding` | страница проекта. Адрес собирается из `Name`, **сейчас это временная заглушка** |
| всё остальное | «Такой страницы нет» |

### Технические заметки

- Таблица читается через `gviz/tq?tqx=out:csv`: этот адрес отдаёт CSV и разрешает браузеру читать его с другого сайта (CORS). «Опубликовать в интернете» не нужно.
- CSV разбирается библиотекой `papaparse`, роутинг — `react-router`.
- Dropbox-ссылки: в коде `dl=0` → `raw=1`.
- Если превью не загрузилось за 8 секунд, карточка встаёт с пропорцией 3:2 и потом подстраивается. Если ссылка битая, рамка остаётся серой.
- Карточки рисуются в браузере. Поисковики индексируют такие сайты хуже, но для портфолио это некритично: `title` и `description` страницы прописываются в `index.html`.
